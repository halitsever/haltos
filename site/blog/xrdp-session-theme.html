Why xrdp opens a different desktop, and how to theme it

You connect over RDP and get XFCE instead of Plasma, or Plasma with stock colours instead of your theme, or a black screen. All three come from the same fact: xrdp starts its own session, separate from the one on the machine's screen, and reads a different file to decide what to start. This post explains that file and how HaltOS gets its theme into the RDP session.

xrdp starts its own session

When you log in through xrdp, it does not attach to the desktop on the machine's monitor. It starts a new X11 session for your user, using xorgxrdp as the X server, and runs a script to decide which desktop to launch. On Debian and Ubuntu that script ends up reading ~/.xsession if you have one. Without it, the system default session manager starts, which on many servers is whatever desktop was installed first, often XFCE because it is a common lightweight choice for remote access.

So "xrdp looks different" usually means one of:

What you seeWhy
XFCE (or another desktop) instead of PlasmaNo ~/.xsession, or it starts a different desktop
Plasma, but stock colours and fontsThe theme was never applied for this user, or was applied in a different session type
A black screenThe session failed to start, or your user already has a desktop open elsewhere

Pick the desktop with ~/.xsession

For Plasma, this is the file claude-code-vps writes for its user, and HaltOS relies on it:

export XDG_SESSION_TYPE=x11
export XDG_CURRENT_DESKTOP=KDE
export DESKTOP_SESSION=plasma
exec startplasma-x11

Save it as ~/.xsession in your home folder, disconnect, and connect again. The variables tell applications which desktop they are in, and startplasma-x11 starts Plasma's X11 session. xrdp needs X11; Plasma's Wayland session does not run under it, so the plasma-session-x11 and kwin-x11 packages must be installed. The KDE Plasma over xrdp post has the full package list.

For XFCE the same file would end in exec startxfce4. Whichever desktop the file starts is the one whose theme settings apply.

Your theme in the RDP session

Plasma stores its look per user under ~/.config (colour scheme, widget style, fonts, panel layout). A Plasma session over RDP for the same user reads the same files as a local one, so a theme set locally also shows remotely, and the other way round. When it does not, the theme was usually set for another user, or only partly applied.

Some parts need a running Plasma shell to apply: the panel layout and the wallpaper live inside plasmashell. Installing a theme from an SSH session, with no desktop running, can only write the config files. HaltOS handles that case explicitly. When install.sh user runs without a graphical session, it:

  1. writes every config file it can, and applies the colour scheme with QT_QPA_PLATFORM=offscreen so it lands in kdeglobals without a display;
  2. adds an autostart entry, ~/.config/autostart/haltos-firstrun.desktop, that runs install.sh firstrun;
  3. on your first RDP login, that entry waits up to 30 seconds for plasmashell, applies the panel script, the wallpaper and the colour scheme, then deletes itself.

The README puts it in one line: connect over RDP afterwards and HaltOS finishes the panel and wallpaper on the first login. The screenshot above is that first-login result.

Black screen

The usual causes, in the order worth checking:

  1. Already logged in elsewhere. If the same user has a desktop open on the machine's own screen, a second session for that user often fails to start properly. Log out locally, or use a separate user for RDP.
  2. The session command exits. A typo in ~/.xsession, a desktop that is not installed, or a missing execute path ends the session at once. Test the last line by hand over SSH: command -v startplasma-x11.
  3. The X11 session is missing. On Plasma 6, the X11 session is a separate package. Without plasma-session-x11 there is no startplasma-x11 to run.

xrdp keeps a per-user log at ~/.xorgxrdp.*.log and session errors in ~/.xsession-errors, which usually name the problem.

Login screens over RDP

xrdp shows its own login dialog and starts the session directly, so the display manager's login screen, SDDM on Plasma, never appears over RDP. Themes for it only show on a local display, as covered in SDDM themes. On a server set up by claude-code-vps, SDDM is disabled entirely and the machine boots to a text console.

Make it fast over RDP

Without a GPU, everything in an RDP session is drawn in software and sent as compressed images. Flat colours compress better than gradients and blur. HaltOS's flat monochrome theme was chosen partly for that reason; the monochrome desktop post explains the rest. To try the theme on your own Plasma 6 machine, see the HaltOS KDE Plasma theme.

Questions

How do I make xrdp start KDE Plasma instead of XFCE?

Put a ~/.xsession file in your home folder that exports XDG_SESSION_TYPE=x11, XDG_CURRENT_DESKTOP=KDE and DESKTOP_SESSION=plasma, then runs exec startplasma-x11. Log out of RDP and connect again.

Why does xrdp show a black screen after login?

Common causes are the same user already being logged in to a desktop on the machine's own screen, or a session command that exits right away, such as a missing desktop or a broken ~/.xsession.

Does my desktop theme apply in an xrdp session?

Theme settings in ~/.config belong to your user, so the same desktop picks them up. A different desktop, such as XFCE instead of Plasma, has its own settings and looks different.
