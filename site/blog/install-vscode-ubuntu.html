Three ways to get VS Code on Ubuntu, and the one HaltOS uses

Visual Studio Code is not in Ubuntu's own archive, so every install route starts at Microsoft. The VS Code docs describe three: a .deb you download, Microsoft's apt repository, and a snap. This post covers each one, then shows the exact commands HaltOS runs on a server, tested in an Ubuntu 26.04 container on 28 November 2026.

Option 1: the .deb file

The VS Code Linux docs link a .deb download. Install it with apt so dependencies are resolved:

sudo apt install ./code_*.deb

During the install the package asks whether to add Microsoft's apt repository and signing key. Say yes and you end up with option 2. For scripts, the docs give a debconf answer to set first:

echo "code code/add-microsoft-repo boolean true" | sudo debconf-set-selections

Option 2: Microsoft's apt repository

This is what the docs describe as the manual setup. Install the key:

sudo apt install wget gpg
wget -qO- https://packages.microsoft.com/keys/microsoft.asc | sudo gpg --dearmor -o /usr/share/keyrings/microsoft.gpg

Create /etc/apt/sources.list.d/vscode.sources in the deb822 format:

Types: deb
URIs: https://packages.microsoft.com/repos/code
Suites: stable
Components: main
Architectures: amd64,arm64,armhf
Signed-By: /usr/share/keyrings/microsoft.gpg

Then:

sudo apt update
sudo apt install code

Signed-By ties the repository to that one key, instead of trusting it for every source on the system. The docs add that the repository can lag a new release by up to three hours because of manual signing.

Option 3: the snap

sudo snap install --classic code

--classic gives the snap normal access to the file system, which an editor needs. The docs say the snap daemon updates VS Code in the background.

How HaltOS installs it

HaltOS installs VS Code on the server during install.sh system, with the repository route (install.sh):

command -v code >/dev/null && return 0
[ -f /usr/share/keyrings/microsoft.gpg ] ||
    curl -fsSL --retry 5 --retry-delay 10 https://packages.microsoft.com/keys/microsoft.asc | gpg --dearmor --yes -o /usr/share/keyrings/microsoft.gpg
printf 'Types: deb\nURIs: https://packages.microsoft.com/repos/code\n...' >/etc/apt/sources.list.d/vscode.sources
echo "code code/add-microsoft-repo boolean false" | debconf-set-selections
apt-get update -qq
DEBIAN_FRONTEND=noninteractive apt-get install -y -qq code

Three details. It skips everything when code is already on the PATH. It retries the key download, because packages.microsoft.com answers bursts of requests with HTTP 429. And it answers the debconf question with false: the sources file is already written, and the package would otherwise add a second copy of the same repository.

Tested in a container

The same steps ran in an ubuntu:26.04 container. Before the repository was added, apt-cache policy code showed no candidate. After it:

code:
  Installed: (none)
  Candidate: 1.148.0-1795526052

The install succeeded, code --version printed 1.148.0, and /etc/apt/sources.list.d/ held only ubuntu.sources and vscode.sources, so the debconf answer did its job.

Over RDP

On a HaltOS server VS Code runs inside the KDE Plasma session you reach over RDP. HaltOS also copies its HaltMono colour theme into ~/.vscode/extensions, which VS Code loads on its next start without the code command or a network connection. For the desktop itself, see KDE Plasma over RDP with xrdp, and for the editor font, installing fonts on Ubuntu.

Removing it

sudo apt remove code
sudo rm /etc/apt/sources.list.d/vscode.sources /usr/share/keyrings/microsoft.gpg
sudo apt update

For the snap, sudo snap remove code.

Questions

What is the best way to install VS Code on Ubuntu?

Microsoft's apt repository. VS Code then updates with the rest of the system through apt. The .deb from the website can add the same repository for you, and the snap updates itself in the background.

Is VS Code in the Ubuntu repositories?

No. In ubuntu:24.04 and ubuntu:26.04 containers, apt had no candidate for the package code until Microsoft's repository was added.

Why does VS Code ask about adding the Microsoft repository?

The .deb package offers to install the apt repository and signing key so that VS Code updates through apt. Answer code code/add-microsoft-repo with debconf-set-selections to skip the prompt in scripts.
