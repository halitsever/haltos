sh is not bash on Ubuntu: what breaks and how to tell

On Ubuntu, sh and bash are two different programs. A script that works when you type bash script.sh can fail with a syntax error under sh script.sh, because Ubuntu's /bin/sh is dash, a smaller shell that only does what POSIX requires. This post shows the errors dash really prints, and how HaltOS keeps one of its scripts POSIX on purpose.

What /bin/sh is on Ubuntu

$ ls -l /bin/sh
lrwxrwxrwx 1 root root 4 Feb  2  2026 /bin/sh -> dash

That is from an ubuntu:26.04 container; 24.04 shows the same link. dash is a small shell that implements the POSIX shell language and little more. bash, version 5.3 on Ubuntu 26.04, implements POSIX plus a lot of extensions.

So the shebang decides:

First lineRuns in
#!/bin/shdash
#!/bin/bashbash
#!/usr/bin/env bashthe first bash on PATH
none, started with sh filedash
none, started with bash filebash

The same script in both

greet() { local name="$1"; echo "hi $name"; }
greet you
if [[ "abc" == a* ]]; then echo "match"; fi
arr=(one two); echo "${arr[1]}"
echo {1..3}
echo "$((2**3))"

Under bash:

hi you
match
two
1 2 3
8

Under sh, which is dash:

hi you
bashisms.sh: 3: [[: not found
bashisms.sh: 4: Syntax error: "(" unexpected

The exit code was 2. The [[ line only printed an error and carried on, which is worse than stopping, since the if silently took the false branch. The array on line 4 was a syntax error that ended the script. Run one at a time, the other two lines also differ: dash printed {1..3} literally, and $((2**3)) failed with arithmetic expression: expecting primary: "2**3".

local worked. dash supports it even though POSIX does not define it, which is why ShellCheck still warns about it in sh mode.

Common bashisms and POSIX versions

bashPOSIX sh
[[ $a == b* ]]case $a in b*) ... ;; esac
[ "$a" == "$b" ][ "$a" = "$b" ]
arrays arr=(a b)set -- a b and "$@", or separate variables
{1..3}seq 1 3 or a while loop
$((2**3))$((2*2*2))
function f { }f() { }
source file. file
echo -eprintf
$'\n'printf '\n'

The POSIX shell command language is the reference for what sh must support.

When to choose which

Write for bash when the script is yours to run and bash is guaranteed, which it is on Ubuntu. Say so with #!/usr/bin/env bash and use the features freely. HaltOS's install.sh and bootstrap.sh do that, and turn on bash's strict mode near the top (set -euo pipefail and set -Eeuo pipefail).

Write for POSIX sh when another program starts the script with sh. HaltOS's SSH login banner, system/motd/00-haltos, is that case: Ubuntu's update-motd runs the files in /etc/update-motd.d, so the script starts with #!/bin/sh and sticks to [ ], $(...), case and printf. The MOTD post shows the full script.

Catching bashisms automatically

ShellCheck knows both dialects. On a #!/bin/sh script, or with -s sh, it flags bash-only syntax with SC3xxx codes, for example SC3014 for == in [ ] and SC3043 for local. HaltOS's CI runs shellcheck -S warning -s sh system/motd/00-haltos to keep the banner POSIX. The ShellCheck post has the full setup.

Ubuntu also packages checkbashisms in devscripts, a narrower tool that does only this one job.

Questions

Is sh the same as bash on Ubuntu?

No. On Ubuntu 24.04 and 26.04, /bin/sh is a symbolic link to dash. Scripts run with sh or with a #!/bin/sh shebang are interpreted by dash, which lacks many bash features.

Why does my script say [[: not found?

It is running in dash, which has no [[ ]] keyword. Run it with bash, change the shebang to #!/usr/bin/env bash, or rewrite the test with [ ] and POSIX operators.

Should I write scripts for sh or bash?

Use bash when you need its features and can rely on bash being installed. Use POSIX sh for scripts other programs run with sh, such as files in /etc/update-motd.d, and check them with shellcheck -s sh.
