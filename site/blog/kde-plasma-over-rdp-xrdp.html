KDE Plasma over RDP on a VPS with xrdp

A VPS has no screen, no GPU and nobody sitting in front of it. You can still run a full KDE Plasma desktop on it and reach it from any RDP client. Here is how the pieces fit.

xrdp and the X11 session

xrdp speaks the RDP protocol and xorgxrdp gives it an X server to draw into. Plasma also runs on Wayland, but xrdp sessions use X11, so install the X11 session:

apt install kde-plasma-desktop plasma-session-x11 kwin-x11 xrdp xorgxrdp

When you connect, xrdp starts whatever your ~/.xsession says. For Plasma:

export XDG_SESSION_TYPE=x11
export XDG_CURRENT_DESKTOP=KDE
export DESKTOP_SESSION=plasma
exec startplasma-x11

No display manager

Nobody logs in at the console of a server, so a graphical login screen only costs memory. Boot to the text target and let xrdp start sessions on demand:

systemctl disable --now sddm
systemctl set-default multi-user.target

One annoying prompt

Out of the box, Plasma over xrdp often greets you with a password prompt about creating a colour profile. A small polkit rule that allows colour manager actions for members of the users group makes it go away.

Fast without a GPU

Without a GPU, everything is drawn in software. The desktop is still perfectly usable, but heavy effects cost CPU and bandwidth. A flat theme with few gradients and little animation compresses better over RDP and feels snappier. That is part of why HaltOS uses a flat, monochrome look.

Screen size and clipboard

The resolution follows your RDP client window, and copy and paste works between your machine and the desktop. Most clients also offer full screen and multi-monitor modes.

All of it in one command

claude-code-vps does all of the above, and HaltOS adds a theme and Claude Code tooling on top, with one command on a fresh Ubuntu 25.04 or newer server.
