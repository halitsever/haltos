Finding shell script bugs before they run, with ShellCheck

ShellCheck is a static analyser for shell scripts. It reads a script without running it and points at quoting mistakes, commands whose failure is ignored and features your shell does not have. HaltOS runs it on every pull request. This post shows its output on a small broken script and the exact settings HaltOS uses, all run with ShellCheck 0.11.0.

Run it

sudo apt install shellcheck
shellcheck script.sh

or without installing:

docker run --rm -v "$PWD:/mnt" -w /mnt koalaman/shellcheck:stable script.sh

In Ubuntu containers on 28 November 2026, apt offered ShellCheck 0.9.0 on 24.04 and 0.11.0 on 26.04. The Docker image stable was 0.11.0.

A broken script

#!/bin/sh
dir=$1
files=$(ls $dir)
if [ $files == "" ]; then
  echo "empty"
fi
cd $dir
rm -rf $dir/tmp/*

ShellCheck's report, shortened to one line per finding with -f gcc:

demo.sh:3:12: note: Double quote to prevent globbing and word splitting. [SC2086]
demo.sh:4:6: note: Double quote to prevent globbing and word splitting. [SC2086]
demo.sh:4:13: warning: In POSIX sh, == in place of = is undefined. [SC3014]
demo.sh:7:1: warning: Use 'cd ... || exit' or 'cd ... || return' in case cd fails. [SC2164]
demo.sh:7:4: note: Double quote to prevent globbing and word splitting. [SC2086]
demo.sh:8:8: note: Double quote to prevent globbing and word splitting. [SC2086]

The default output prints each line with a caret under the problem and a suggested fix, such as cd "$dir" || exit. The exit code was 1, which is what fails a CI job.

The worst bug here is the pair on lines 7 and 8. If cd fails, the script keeps going and rm -rf runs from wherever it was. If $dir is empty, the path becomes /tmp/*. Quoting and || exit fix both.

Severity levels

Every finding has a level: error, warning, info (shown as note in gcc format) or style. -S sets the minimum:

$ shellcheck -S warning -f gcc demo.sh
demo.sh:4:13: warning: In POSIX sh, == in place of = is undefined. [SC3014]
demo.sh:7:1: warning: Use 'cd ... || exit' or 'cd ... || return' in case cd fails. [SC2164]

The quoting notes disappear. That trade-off is why many projects start with -S warning on old code and tighten it later.

Pick the shell: -s

ShellCheck reads the shebang. Forcing another dialect changes the rules. With -s bash the == warning goes away, because bash accepts == inside [ ]. HaltOS's install.sh is bash; checked as POSIX sh with -s sh it produced 24 SC3043 findings, one for every local, plus others for [[ ]] and similar. That is the difference the bash vs sh post is about.

Directives

To accept a finding on purpose, put a comment on the line before:

# shellcheck disable=SC1090  # written at runtime on the server, not part of the repo
[ -r "$CONF" ] && c=$(. "$CONF" && echo "${CHANNEL:-stable}")

That line is from install.sh. SC1090 means ShellCheck cannot follow a source whose path is a variable. HaltOS also uses # shellcheck shell=bash at the top of shell/haltos-prompt.sh, a file that is sourced and has no shebang, to tell ShellCheck which dialect it is.

Each code has a wiki page, for example SC2086, with the reasoning and the fix.

How HaltOS runs it in CI

The ci.yml workflow runs two commands:

shellcheck -S warning install.sh bootstrap.sh shell/haltos-prompt.sh plasma/scripts/windeco.sh tools/clean-shot.sh tools/release.sh tests/system.sh tests/user.sh tests/lib.sh
shellcheck -S warning -s sh system/motd/00-haltos

The second line exists because the SSH login banner, 00-haltos, is a POSIX sh script: Ubuntu runs the files in /etc/update-motd.d with its default shell, and HaltOS keeps that one free of bashisms. The MOTD post shows what the script prints. Both commands passed with ShellCheck 0.11.0 on the current main.

The list is explicit, so a new script is not checked until someone adds it. The repository's AGENTS.md tells contributors to do exactly that.

In the editor

The VS Code extension "ShellCheck" and most other editors run the same binary while you type, which catches the quoting notes long before CI does.

Questions

How do I install ShellCheck on Ubuntu?

sudo apt install shellcheck. On 28 November 2026 Ubuntu 24.04 offered version 0.9.0 and Ubuntu 26.04 version 0.11.0. The koalaman/shellcheck Docker image works without installing anything.

How do I ignore a ShellCheck warning?

Put a directive comment on the line before the command, for example # shellcheck disable=SC2086. Add a short reason after it so the next reader knows why.

Does ShellCheck check POSIX sh?

Yes. It reads the shebang, and -s sh forces POSIX mode. In that mode it flags bash-only features such as [[ ]], arrays and local.
